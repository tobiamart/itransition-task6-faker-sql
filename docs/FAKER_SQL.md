# Faker SQL – fake user data in PostgreSQL

Faker SQL is a set of PostgreSQL stored functions and procedures (schema `faker`) that generate
realistic, reproducible fake people: name, address, geolocation, physical attributes, phone number
and e-mail. All generation happens in the database; an application only calls one function:

```sql
SELECT * FROM faker.generate_users('de_DE', 2024, 0, 3);   -- locale, seed, batch, batch size
```

| seq | full_name | address | phone | email |
|---|---|---|---|---|
| 0 | Zlatko Jacob | Kyritzer Straße 70, 50348 Illertissen | +49 790 2346781 | jacob.zlatko@gmail.com |
| 1 | Frau Louise Eberharter | Poststraße 92, Whg. 3, 10329 Bad Mergentheim | +49 406 7663460 | louise_eberharter27@gmail.com |
| 2 | Frau Dr. Freia Peukert | Friedhofgasse 3, Whg. 25, 82535 Freital | 0413 6234990 | freiapeukert@web.de |

Supported locales: `en_US` (English, United States), `de_DE` (German, Germany), `pl_PL` (Polish, Poland).

## Installation

Requires PostgreSQL 13 or newer (tested on 16 and 18; both produce identical data). Run the three scripts in order:

```bash
psql "$DATABASE_URL" -f sql/01_schema.sql      # tables
psql "$DATABASE_URL" -f sql/02_functions.sql   # functions and procedures
psql "$DATABASE_URL" -f sql/03_data.sql        # lookup data + CALL faker.rebuild_picks()
```

or `python tools/setup_db.py "$DATABASE_URL"`. `sql/03_data.sql` is generated by
`tools/build_data_sql.py` from the [Faker](https://github.com/joke2k/faker) name lists (MIT licence)
and hand-written vocabularies.

## How reproducibility works

Nothing in Faker SQL uses `random()` or any global state. Every random value is a pure function of

```
user key = user_key(locale, seed, batch, index)   -- 62-bit
value    = rand(user key, stream)                 -- stream = which field / which draw
```

* The same `(locale, seed, batch, index)` always produces the same user, on any server, whatever the
  batch size: user 3 of batch 5 is identical whether batches have 4 or 10 users.
* Users do not depend on each other, so batch 1000 is generated as quickly as batch 0 (no need to
  generate the previous batches).
* Each field uses its own stream numbers, so adding a field or changing one format never changes the
  other fields of the same user.

| Streams | Used by |
|---|---|
| 100–119 | `person` (gender 100, format 101, first 102, middle 103, last 104, second surname 105, title 106, suffix 107, academic degree 108, rendering 110) |
| 200–279 | `address` (format 200, region 201, ZIP 202, street 203/210, city 204/220, building 205/230, apartment 206/240, postcode 207/250, rendering 260) |
| 300–301 | `geo` |
| 400–405 | `physical` (height 400–401, BMI 402–403, eyes 404, hair 405) |
| 500–501 | `phone` |
| 600–602 | `email` |

`render` and `fill_pattern` derive sub-streams `stream * 128 + i` from the stream they get, so one
template can use many random digits without clashing with other fields.

## Data model

All lookup tables are shared by every locale and distinguished by a `locale` column; a new locale or
a new word list is only new rows.

| Table | Columns | Content |
|---|---|---|
| `locales` | code, name, language, country, units | One row per locale; `units` is `metric` or `imperial`. |
| `names` | locale, kind (`first`/`last`), gender (`M`/`F`/NULL), value, weight | NULL gender = used for both. 9,349 names. |
| `words` | locale, category, value, weight | Titles, street words, cities, domains, eye colours… |
| `formats` | locale, category, pattern, weight | Templates for names, addresses, phones, e-mails… |
| `regions` | locale, name, abbr, postal_min, postal_max, weight | States / voivodeships, weighted by population; US states carry their ZIP range. |
| `physical_norms` | locale, gender, height_mean, height_sd, bmi_mean, bmi_sd | Parameters of the normal distributions. |
| `picks` | locale, category, cum_hi, value, ref_id | Derived sampling index (see `rebuild_picks`). |

Sizes per locale (first names × last names give 0.6–2.8 million distinct name pairs before middle
names, titles and formats are counted, enough for 100,000–1,000,000 users without visible repetition):

| Locale | First names (M / F) | Last names | Cities | Street words | Name / address / phone / e-mail formats |
|---|---|---|---|---|---|
| en_US | 322 / 381 | 1,000 | generated from 7 prefixes × names × 19 suffixes | 92 + 99 ordinals + surnames | 7+7 / 6 / 7 / 9 |
| de_DE | 1,000 / 1,003 | 1,400 (DE + AT + CH) | 392 | 91 roots + 23 fixed + surnames | 7+8 / 5 / 8 / 9 |
| pl_PL | 100 / 53 | 3,890 (with female forms) | 200 | 400 | 6+7 / 4 / 7 / 9 |

In 100,000 generated `en_US` users 89% of full names and 94% of e-mail addresses are unique;
every phone number and every full name + address combination is unique.

## Entry points

### generate_users

```sql
faker.generate_users(p_locale text, p_seed bigint, p_batch integer DEFAULT 0, p_size integer DEFAULT 10)
RETURNS TABLE (seq bigint, batch integer, idx integer,
               full_name text, gender char(1), title text, first_name text, middle_name text, last_name text,
               address text, street text, building text, apartment text, city text, region text, postcode text,
               latitude double precision, longitude double precision,
               height_cm numeric, weight_kg numeric, height text, weight text, eye_color text, hair_color text,
               phone text, email text)
```

| Argument | Description |
|---|---|
| `p_locale` | Locale code from `faker.list_locales()`. Unknown codes raise an error. |
| `p_seed` | Any bigint. Different seeds give unrelated data sets. |
| `p_batch` | 0-based batch number (`>= 0`). Request the next batch with `p_batch + 1`. |
| `p_size` | Users per batch, 1 to 1,000,000. |

`seq = batch * size + idx` is the user's position for display. `address` is the formatted one-line
address; `street`, `building`, `apartment`, `city`, `region`, `postcode` are its parts (apartment is
NULL when the chosen address format has none). `height`/`weight` are display strings in the locale's
units, `height_cm`/`weight_kg` the raw values.

Algorithm: for each index `i` it computes `k = user_key(locale, seed, batch, i)` and calls
`person`, `address`, `geo`, `physical`, `phone` and `email` with that key.

```sql
SELECT full_name, email FROM faker.generate_users('en_US', 42, 7, 10) WHERE idx = 3;
-- the same row as:
SELECT full_name, email FROM faker.generate_users('en_US', 42, 7, 4) WHERE idx = 3;
```

### benchmark

```sql
faker.benchmark(p_locale text DEFAULT 'en_US', p_users integer DEFAULT 10000, p_seed bigint DEFAULT 1)
RETURNS TABLE (locale text, users integer, seconds numeric, users_per_second numeric)
```

Generates `p_users` users in a single `generate_users` call and measures the elapsed time with
`clock_timestamp()` inside the database, so network latency is excluded.

```sql
SELECT * FROM faker.benchmark('pl_PL', 20000);
```

```sql
faker.list_locales() RETURNS TABLE (code text, name text)
```

## Field generators

All take the user key from `user_key` and read their vocabularies and templates from the lookup
tables, so they work for every locale without locale-specific code.

### person

```sql
faker.person(p_locale text, p_key bigint) RETURNS faker.person_t
-- person_t = (gender char(1), title text, first_name text, middle_name text, last_name text, full_name text)
```

1. Gender: `F` when `rand(key, 100) < 0.5`, otherwise `M`.
2. A name format is drawn from the locale's `name:M` or `name:F` formats, e.g. for `en_US`:
   `{first} {last}` (45%), `{first} {middle_initial}. {last}` (15%), `{title} {first} {last}` (12–14%),
   `{first} {middle} {last}`, `{first} {last} {suffix}` (Jr., PhD…), `{first} {last}-{last2}`.
   `de_DE` adds `{title} {academic} {first} {last}` (Frau Dr. …) and `{first}-{middle} {last}`
   (Hans-Peter …); `pl_PL` adds `{academic} …` (dr, mgr inż.) and double surnames for women.
3. Only the parts the format uses are drawn: first and last name from `names` by weight (US names use
   real frequency weights), a middle name different from the first name, a title for the gender, etc.
4. Polish surnames have gendered forms (Kowalski / Kowalska); `names` stores both, with the gender.

```sql
SELECT * FROM faker.person('pl_PL', faker.user_key('pl_PL', 7, 0, 3));
-- F | NULL | Elżbieta | NULL | Wolff | Elżbieta Wolff
```

### address

```sql
faker.address(p_locale text, p_key bigint) RETURNS faker.address_t
-- address_t = (street, building, apartment, city, region, region_abbr, postcode, full_address)
```

1. Region drawn by population weight from `regions` (US states, German Länder, Polish voivodeships).
2. If the region has a postal range (US states) a ZIP code is drawn uniformly from it, so the ZIP
   matches the state.
3. Street, city, building number, apartment and postcode are each rendered from the locale's
   formats, e.g. `en_US` streets `{street_word} {street_suffix}` (Oak Avenue), `{street_ordinal}
   {street_suffix}` (2nd Road), `de_DE` streets `{street_root}{street_suffix}` (Lindenweg),
   `{any_first}-{any_last}-{street_suffix_long}` (Hans-Müller-Straße), `{city_any}er Straße`
   (Kyritzer Straße), `pl_PL` streets `{street_prefix} {street_name}` (ul. Leśna). US cities are
   generated from parts (`{city_prefix} {any_first}{city_suffix}` → Lake Alisonhaven); German and
   Polish cities come from lists of real towns.
4. The full address is rendered with a weighted `address` format: with or without apartment / suite,
   state name or abbreviation, ZIP+4, PO box, `Whg.` (German flat), `m.` or `/` (Polish flat),
   voivodeship suffix and so on.

```sql
SELECT full_address FROM faker.address('en_US', faker.user_key('en_US', 7, 0, 1));
-- 269 2nd Road, Suite 51, Lake Alisonhaven, MO 65794-1406
```

### geo

```sql
faker.geo(p_key bigint, OUT latitude double precision, OUT longitude double precision)
```

Uniform distribution on the sphere (constant probability per unit of area):

```
longitude = 360·u − 180
latitude  = asin(2·v − 1)        (in degrees)
```

with independent uniform `u = rand(key, 301)`, `v = rand(key, 300)`, rounded to 10⁻⁶ degree (≈ 0.1 m)
so that the last bit of `asin` on different CPUs cannot change the result. Drawing the latitude uniformly
in [−90°, 90°] would be wrong: it puts as many points in the small polar caps as around the equator.
The area of the band between the equator and latitude φ is proportional to sin φ, so sin φ must be
uniform on [−1, 1], which is what `asin(2v − 1)` achieves (inverse-CDF sampling). Check on 100,000
points: mean of sin(latitude) = −0.0005, share of points with |latitude| < 30° = 0.503 (exact: 0.5).

### physical

```sql
faker.physical(p_locale text, p_key bigint, p_gender char) RETURNS faker.physical_t
-- physical_t = (height_cm numeric, weight_kg numeric, height text, weight text, eye_color text, hair_color text)
```

* Height ~ Normal(mean, sd) from `physical_norms` for the locale and gender, e.g. US men 175.4 ± 7.4 cm,
  German women 166.2 ± 6.6 cm.
* Body-mass index ~ Normal(mean, sd), at least 16.5; weight = BMI × height², so taller people are
  heavier, as in real data.
* Eye and hair colour are discrete weighted choices with localized words and frequencies
  (US: Brown 45%, Blue 27%, Hazel 18%…; DE: Blau 35%, Braun 30%…; PL: niebieskie, piwne…).
* Text is in feet/inches and pounds for `imperial` locales, otherwise centimetres and kilograms.

On 100,000 users the sample mean and standard deviation of height were 175.3 / 7.42 (men) and
161.7 / 7.00 (women) for parameters 175.4 / 7.4 and 161.7 / 7.0.

### phone

```sql
faker.phone(p_locale text, p_key bigint) RETURNS text
```

A weighted `phone` format of the locale filled by `fill_pattern`. `en_US`: `(!##) !##-####`,
`+1 !## !## ####`, `1-!##-!##-####`, `(!##) !##-#### x###`…; `de_DE`: `0%## #######`,
`+49 (0)%## ### ###`, `015# ########`…; `pl_PL`: `+48 %## ### ###`, `(%#) ### ## ##`…
(`!` = digit 2–9 so US area codes and exchanges never start with 0 or 1).

### email

```sql
faker.email(p_locale text, p_key bigint, p_first text, p_last text) RETURNS text
```

Builds the local part from the person's names with a weighted format (`{first}.{last}`,
`{f}{last}`, `{first}_{last}##`, `{last}{f}`, `{first}.{last}####`…) and a domain chosen by local
popularity (gmail.com, yahoo.com… / web.de, gmx.de… / wp.pl, onet.pl…). Names go through `slugify`.

```sql
SELECT faker.email('de_DE', faker.user_key('de_DE', 7, 0, 1), 'Jürgen', 'Groß');   -- juergen_gross38@gmail.com
```

## Random numbers

### hash32

```sql
faker.hash32(x bigint) RETURNS bigint      -- 0 <= result < 2^32
```

The "lowbias32" integer hash by Chris Wellons, a bijection on 32-bit integers with very low bias:

```
x ^= x >> 16;  x *= 0x7feb352d;  x ^= x >> 15;  x *= 0x846ca68b;  x ^= x >> 16    (mod 2^32)
```

PostgreSQL has no unsigned 32-bit type, so values are kept in `bigint` and masked with `& 4294967295`;
the second multiplication is split into two 16-bit halves to stay below 2^63.

### user_key

```sql
faker.user_key(p_locale text, p_seed bigint, p_batch integer, p_index integer) RETURNS bigint
faker.user_key_salted(p_salt bigint, p_seed bigint, p_batch integer, p_index integer) RETURNS bigint
```

Two independent hash chains, each `h = hash32(h XOR hash32(part + constant_i))` over the parts
(seed low 32 bits, seed high 32 bits, batch, index), start from the locale salt
(`locale_salt(text)`, a hash of the locale code's characters). The result is `(h1 << 30) XOR h2`
(62 bits), so collisions between users are practically impossible. `generate_users` computes the
salt once per batch and calls `user_key_salted`.

### rand

```sql
faker.rand(p_key bigint, p_stream integer) RETURNS double precision      -- 0 < result < 1
```

`h = lowbias32((key >> 30) XOR stream·0x9E3779B9)`, then `h = lowbias32(h XOR (key & 0xFFFFFFFF))`;
returns `(h + 0.5) / 2^32`. It never returns exactly 0 or 1, which keeps `ln(u)` in Box–Muller finite.

### rand_int

```sql
faker.rand_int(p_key bigint, p_stream integer, p_lo bigint, p_hi bigint) RETURNS bigint
```

`p_lo + floor(rand · (p_hi − p_lo + 1))`, uniform on the inclusive range.

### rand_normal

```sql
faker.rand_normal(p_key bigint, p_stream integer, p_mean double precision, p_sd double precision)
```

Box–Muller transform of two independent uniforms `u1 = rand(key, stream)`, `u2 = rand(key, stream + 1)`:

```
z = sqrt(−2 ln u1) · cos(2π u2)          z ~ Normal(0, 1)
result = mean + sd · z
```

It consumes two streams (`stream`, `stream + 1`).

## Sampling and templates

### pick

```sql
faker.pick(p_locale text, p_category text, p_u double precision) RETURNS text
faker.pick_ref(p_locale text, p_category text, p_u double precision) RETURNS integer   -- source row id
```

Weighted choice by inverse-CDF on the cumulative weight index `faker.picks`: returns the first row
of `(locale, category)` whose cumulative share `cum_hi` is greater than `p_u`. One index range scan,
O(log n). Categories: every `words.category`, `first:M`, `first:F`, `last:M`, `last:F` for names,
`fmt:<format category>` for templates and `region`.

```sql
SELECT faker.pick('de_DE', 'first:F', 0.5);   -- Jaqueline
```

### rebuild_picks

```sql
CALL faker.rebuild_picks();
```

Stored procedure that rebuilds `faker.picks` from `names`, `words`, `formats` and `regions`: for each
`(locale, category)` it orders rows by id and stores `cum_hi = running sum of weight / total weight`
(the last row gets exactly 1.0). Names with NULL gender are added to both the `M` and `F` lists.
Run it after changing lookup data.

### fill_pattern

```sql
faker.fill_pattern(p_pattern text, p_key bigint, p_stream integer) RETURNS text
```

| Symbol | Replaced by |
|---|---|
| `#` | digit 0–9 |
| `%` | digit 1–9 |
| `!` | digit 2–9 |
| `?` | letter A–F (building and flat letters such as 12B) |

Character `i` uses `rand(key, stream · 128 + i)`; other characters are copied.

```sql
SELECT faker.fill_pattern('(!##) !##-####', 12345, 7);   -- (646) 566-6163
```

### render

```sql
faker.render(p_locale text, p_pattern text, p_key bigint, p_stream integer, p_values jsonb DEFAULT '{}') RETURNS text
```

Fills the digit symbols with `fill_pattern`, then replaces every `{placeholder}` from left to right:

* with `p_values ->> 'placeholder'` when the key is present;
* otherwise with `pick(locale, 'placeholder', …)`, i.e. a weighted word of the same category, so
  `{street_suffix}` draws from `words` category `street_suffix`;
* aliases: `{any_first}` (first name of a random gender), `{any_last}` (last name), `{city_any}` (city).

Placeholder number n uses stream `stream · 128 + 64 + n`. Double spaces and leading/trailing commas
left by empty values are removed.

```sql
SELECT faker.render('en_US', '{building} {street_word} {street_suffix}', 12345, 9, '{"building": "221B"}');
-- 221B Park Street
```

### slugify

```sql
faker.slugify(p_text text) RETURNS text
```

Lower case, German umlauts expanded (ä→ae, ö→oe, ü→ue, ß→ss), other diacritics removed (ł→l, é→e…),
everything except `a–z0-9` dropped: `slugify('Jürgen Łukasz-Müller') = 'juergenlukaszmueller'`.

## Adding a locale

No code changes are needed. Insert:

1. a row in `locales`;
2. first names (`kind = 'first'`, gender `M`/`F`) and last names (gender NULL, or per gender) in `names`;
3. formats `name:M`, `name:F`, `street`, `city`, `building`, `apartment`, `postcode`, `address`,
   `phone`, `email`;
4. words for every placeholder used by those formats, plus `title:M`, `title:F`, `email_domain`,
   `eye_color`, `hair_color` (and `suffix:*`, `academic` if the name formats use them);
5. `regions` and two `physical_norms` rows;

then `CALL faker.rebuild_picks();`.

## Benchmark

`faker.benchmark(locale, 20000)` on the deployed database and locally:

| Environment | en_US | de_DE | pl_PL |
|---|---|---|---|
| Neon free plan (PostgreSQL 18, ARM), run from the deployed app | 3,664 users/s | 3,918 users/s | 4,032 users/s |
| Local PostgreSQL 16 (Windows, x86-64) | 3,634 users/s | 3,928 users/s | 4,009 users/s |

20,000 users per locale in one `faker.benchmark(locale, 20000)` call, time measured inside the database.
Run it yourself on the [Benchmark page](https://faker-sql-generator.vercel.app/benchmark) or with
`SELECT * FROM faker.benchmark('en_US', 20000);`.

Per user the generator draws about 40 random numbers and 15–20 weighted choices; most of the time
is spent in the index lookups of `pick`.
